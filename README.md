# 개인 학습 결과 조회 LMS

구성원이 이름과 생년월일로 로그인해서 본인의 테스트 결과와 프로젝트 발표 평가 결과를 확인하는 웹사이트입니다. 모든 데이터는 여러분의 구글 시트에 저장되고, 관리자는 웹 화면(`/admin`)에서 데이터를 등록·수정할 수 있습니다.

이 문서는 비전공자도 그대로 따라 할 수 있도록 처음부터 끝까지 순서대로 정리했습니다. 중간에 막히면 "문제 해결" 항목을 참고해주세요.

## 전체 흐름 한눈에 보기

1. 구글 클라우드에서 "서비스 계정"을 만든다 (이 웹사이트가 구글 시트에 접근할 수 있는 권한)
2. 구글 시트를 새로 만들고, 서비스 계정과 공유한다
3. 이 프로젝트를 GitHub 저장소에 올린다
4. Vercel에서 그 저장소를 배포하고, 환경변수(비밀 설정값)를 입력한다
5. 구글 시트에 구성원 정보를 입력하고, 관리자 화면에서 테스트/프로젝트 결과를 등록한다

---

## 1단계. 구글 클라우드 서비스 계정 만들기

이 웹사이트가 여러분의 구글 시트를 읽고 쓰려면 "서비스 계정"이라는 전용 로봇 계정이 필요합니다.

1. [Google Cloud Console](https://console.cloud.google.com/)에 접속해서 구글 계정으로 로그인합니다.
2. 화면 상단의 프로젝트 선택 메뉴에서 **새 프로젝트**를 만듭니다. (이름은 자유롭게, 예: `lms-project`)
3. 좌측 메뉴 또는 검색창에서 **"Google Sheets API"**를 검색해서 들어간 뒤 **사용(Enable)** 버튼을 누릅니다.
4. 좌측 메뉴에서 **API 및 서비스 → 사용자 인증 정보(Credentials)**로 이동합니다.
5. 상단의 **+ 사용자 인증 정보 만들기 → 서비스 계정**을 선택합니다.
6. 이름을 입력하고(예: `lms-bot`) 계속 진행해서 서비스 계정을 만듭니다. (역할 지정 단계는 건너뛰어도 됩니다)
7. 생성된 서비스 계정을 클릭 → **키(Keys)** 탭 → **키 추가 → 새 키 만들기 → JSON** 을 선택합니다.
8. JSON 파일이 자동으로 다운로드됩니다. 이 파일을 안전한 곳에 보관하세요. **다른 사람과 공유하거나 GitHub에 올리면 안 됩니다.**

다운로드한 JSON 파일은 이후 단계에서 **파일 전체를 그대로** 사용합니다. `private_key`만 따로 잘라서 복사하면 줄바꿈이 깨져서 로그인 오류(`DECODER routines::unsupported` 등)가 나기 쉬우니, 파일을 열어서 내용을 자르지 말고 통째로 복사해두세요.

## 2단계. 구글 시트 만들기

1. [Google Sheets](https://sheets.google.com)에서 새 스프레드시트를 만듭니다. 제목은 자유롭게 정합니다. (예: "학습 결과 관리")
2. 오른쪽 위 **공유** 버튼을 눌러서, 1단계에서 확인한 서비스 계정 이메일(`...gserviceaccount.com`으로 끝나는 주소)을 추가하고 권한을 **편집자**로 지정합니다.
3. 주소창의 URL을 확인합니다. 아래처럼 생겼습니다.

   ```
   https://docs.google.com/spreadsheets/d/1AbCdEfGhIjKlMnOpQrStUvWxYz/edit
   ```

   `/d/` 와 `/edit` 사이에 있는 `1AbCdEfGhIjKlMnOpQrStUvWxYz` 부분이 **시트 ID**입니다. 이후 단계에서 사용하니 복사해두세요.

### 시트 구조 준비하기 (탭 5개)

이 시스템은 하나의 스프레드시트 안에 아래 5개의 탭(시트)을 사용합니다. 각 탭의 **첫 번째 줄(헤더)**에 아래 컬럼명을 정확히(띄어쓰기 없이) 입력해주세요.

**"구성원" 탭**

| 구성원ID | 이름 | 생년월일 | 과정명 | 기수 | 상태 |
| --- | --- | --- | --- | --- | --- |

**"테스트" 탭**

| 테스트ID | 테스트명 | 과정명 | 기수 | 응시일 | 만점 | 공개여부 |
| --- | --- | --- | --- | --- | --- | --- |

**"테스트결과" 탭**

| 결과ID | 테스트ID | 구성원ID | 총점 | 총평 | 등록일 | 수정일 |
| --- | --- | --- | --- | --- | --- | --- |

**"테스트문항결과" 탭**

| 결과ID | 문항번호 | 배점 | 획득점수 | 감점여부 | 피드백 |
| --- | --- | --- | --- | --- | --- |

**"프로젝트평가" 탭**

| 평가ID | 구성원ID | 프로젝트명 | 발표일 | 강사명 | 기술활용도 | 기능구현완성도 | 문제해결 | 발표전달력 | 총점 | 평가코멘트 | 공개여부 | 등록일 | 수정일 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |

> 팁: 직접 타이핑하기 번거롭다면, 아래 "4단계"까지 마친 뒤 `npm run setup-sheets` 명령을 실행하면 5개 탭과 헤더를 자동으로 만들어줍니다 (컴퓨터에 Node.js가 설치되어 있어야 합니다). 이미 데이터가 있는 탭은 건드리지 않으니 안심하고 실행해도 됩니다.

**"구성원ID", "테스트ID", "결과ID", "평가ID"는 직접 입력할 필요 없습니다.** 관리자 화면이나 일괄 업로드를 통해 데이터를 등록하면 자동으로 생성됩니다. 날짜 컬럼(생년월일, 응시일, 발표일 등)은 `2026-08-10`처럼 하이픈이 들어간 형식으로 입력하는 것을 권장합니다. 셀 서식이 자동으로 "날짜"로 바뀌어 이상하게 보인다면, 해당 열을 선택하고 서식 → 숫자 → 일반 텍스트로 바꿔주세요.

## 3단계. GitHub에 코드 올리기

이 프로젝트 폴더 전체를 여러분의 GitHub 저장소에 새로 만들어 업로드하세요. (평소 하시던 방식대로 업로드하면 됩니다.) `.env.local` 파일은 만들지 않았다면 애초에 없을 것이고, 혹시 로컬에서 테스트하며 만들었더라도 `.gitignore`에 의해 자동으로 GitHub에는 올라가지 않습니다.

---

## 4단계. Vercel에 배포하기

1. [Vercel](https://vercel.com)에 로그인합니다.
2. **Add New → Project**를 선택하고, 방금 올린 GitHub 저장소를 선택해서 Import 합니다.
3. **Environment Variables(환경변수)** 설정 화면에서 아래 4개 값을 입력합니다. (`.env.local.example` 파일에 각 항목 설명이 적혀있습니다)

   | 이름 | 값 |
   | --- | --- |
   | `GOOGLE_SERVICE_ACCOUNT_JSON` | 1단계에서 다운로드한 JSON 키 파일을 텍스트 편집기로 열어서, 처음 `{` 부터 마지막 `}` 까지 **전체 내용을 그대로** 복사해서 붙여넣기 |
   | `GOOGLE_SHEET_ID` | 2단계에서 확인한 시트 ID |
   | `SESSION_SECRET` | 아무 문자열이나 20자 이상으로 직접 만들어 입력 (예: 키보드를 아무렇게나 눌러 만든 문자열) |
   | `ADMIN_PASSWORD` | 관리자 화면(`/admin`) 로그인 비밀번호로 사용할 값 |

   > **중요:** `private_key` 값만 따로 잘라서 넣지 마세요. 줄바꿈이 깨지면서 `DECODER routines::unsupported` 같은 오류가 나는 가장 흔한 원인입니다. 반드시 JSON 파일 **전체**(중괄호 `{ }` 포함)를 하나의 값으로 붙여넣으세요.
   >
   > (예전 방식으로 `GOOGLE_SERVICE_ACCOUNT_EMAIL`과 `GOOGLE_PRIVATE_KEY`를 따로 넣고 싶다면 여전히 가능하지만, `GOOGLE_SERVICE_ACCOUNT_JSON`이 설정되어 있으면 그 값이 우선됩니다.)

4. **Deploy** 버튼을 누르면 몇 분 안에 배포가 완료되고, `https://프로젝트이름.vercel.app` 같은 주소가 생성됩니다.

배포 후 환경변수를 수정했다면, Vercel 프로젝트의 **Deployments** 탭에서 최신 배포를 다시 실행(**Redeploy**)해야 반영됩니다.

## 5단계. 처음 데이터 넣고 확인하기

1. 배포된 주소로 접속해서 `/admin/login`으로 이동한 뒤, 4단계에서 설정한 `ADMIN_PASSWORD`로 로그인합니다.
2. **구성원 관리**에서 구성원을 한 명 등록합니다. (이름, 생년월일 필수)
3. **테스트 관리**에서 테스트를 하나 만들고(예: "C++ 1차 테스트", 만점 100), **결과 관리**로 들어가 방금 등록한 구성원의 문항별 점수를 입력합니다.
4. 테스트 목록에서 **공개로 전환** 버튼을 눌러야 구성원 화면에 결과가 보입니다.
5. 사이트 첫 화면(`/`)으로 돌아가서 등록한 이름과 생년월일로 로그인해서 잘 보이는지 확인합니다.
6. 같은 방식으로 **프로젝트 평가**도 등록하고 공개 상태로 바꿔서 확인합니다.

데이터가 많다면 **일괄 업로드**(`/admin/upload`) 화면에서 CSV 양식을 내려받아 한 번에 등록할 수 있습니다.

## 화면 구성 안내

### 구성원 화면

- `/` : 이름 + 생년월일로 로그인
- `/dashboard` : 본인의 테스트/프로젝트 평가 목록 (공개된 결과만 표시)
- `/dashboard/test/[결과ID]` : 테스트 문항별 점수, 감점 문항, 피드백, 총평
- `/dashboard/project/[평가ID]` : 프로젝트 평가 항목별 점수, 강사 코멘트

### 관리자 화면 (`/admin`)

- **구성원 관리** : 구성원 등록/수정/삭제/검색
- **테스트 관리** : 테스트 생성/수정/삭제, 공개·비공개 전환, 결과 관리 화면으로 이동
- **테스트 결과 관리** (테스트별 "결과 관리" 버튼) : 구성원별 문항 점수·피드백·총평 등록/수정/삭제
- **프로젝트 평가** : 평가 등록/수정/삭제, 항목별 점수(0~5점) 입력, 공개·비공개 전환
- **일괄 업로드** : CSV 파일로 테스트 결과·프로젝트 평가를 한 번에 등록 (검증 실패 시 저장하지 않고 오류 목록을 보여줌)

**공개 여부**는 테스트는 테스트 단위로, 프로젝트 평가는 평가 건별로 관리됩니다. 비공개 상태에서는 관리자 화면에서만 보이고 구성원 화면에는 노출되지 않습니다.

## 로컬 컴퓨터에서 미리 확인해보기 (선택)

Node.js가 설치되어 있다면, 배포 전에 내 컴퓨터에서 먼저 테스트해볼 수 있습니다.

```bash
npm install
cp .env.local.example .env.local   # 그 다음 .env.local을 열어 실제 값 입력
npm run setup-sheets               # (선택) 구글 시트에 탭/헤더 자동 생성
npm run dev
```

브라우저에서 `http://localhost:3000` 으로 접속하면 됩니다.

## 문제 해결

**로그인이 안 돼요 (구성원 화면)**
- 구글 시트 "구성원" 탭에 이름/생년월일이 정확히 일치하는 행이 있는지 확인하세요.
- 생년월일은 형식이 달라도(2000-01-01, 20000101 등) 숫자만 비교하므로 큰 문제는 없지만, 이름에 공백이 섞여있지 않은지 확인해주세요.

**화면에 500 오류가 떠요 / 데이터가 안 보여요**
- Vercel 프로젝트의 환경변수 4개(`GOOGLE_SERVICE_ACCOUNT_JSON`, `GOOGLE_SHEET_ID`, `SESSION_SECRET`, `ADMIN_PASSWORD`)가 모두 정확히 입력되어 있는지 확인하세요.
- 구글 시트가 서비스 계정 이메일과 **편집자**로 공유되어 있는지 확인하세요.
- 시트 탭 이름이 "구성원", "테스트", "테스트결과", "테스트문항결과", "프로젝트평가"와 정확히 일치하는지 확인하세요. (띄어쓰기, 오타 주의)
- 환경변수를 새로 입력했다면 Vercel에서 **Redeploy**를 해야 반영됩니다.

**`DECODER routines::unsupported` 같은 오류가 떠요**
- `GOOGLE_PRIVATE_KEY`를 따로 잘라서 넣었다면 줄바꿈이 깨진 것입니다. `GOOGLE_SERVICE_ACCOUNT_EMAIL`/`GOOGLE_PRIVATE_KEY` 두 값을 지우고, 대신 `GOOGLE_SERVICE_ACCOUNT_JSON` 하나에 JSON 키 파일 **전체 내용**(`{`부터 `}`까지)을 그대로 붙여넣은 뒤 Redeploy 하세요.

**관리자 비밀번호를 잊어버렸어요**
- Vercel 환경변수의 `ADMIN_PASSWORD` 값을 새 값으로 바꾸고 Redeploy 하세요.

## 보안 관련 참고사항

- 관리자 비밀번호(`ADMIN_PASSWORD`)와 `SESSION_SECRET`은 추측하기 어려운 값으로 설정하세요.
- 구글 서비스 계정 키(JSON)는 절대 GitHub 등 외부에 공개하지 마세요.
- 이름/생년월일은 URL에 노출되지 않고, 로그인 후에는 서명된 쿠키(구성원ID만 포함)로 세션을 유지합니다. 구글 시트 원본은 서비스 계정을 통해서만 접근되며 구성원이 직접 열람할 수 없습니다.
- 일괄 업로드 기능은 `xlsx` 라이브러리를 사용합니다. 이 라이브러리는 알려진 보안 이슈(프로토타입 오염)가 있어, **신뢰할 수 있는 사람(관리자 본인)이 만든 파일만** 업로드하는 것을 권장합니다.

## MVP 이후 확장 아이디어

요구사항 정의서 15장에서 언급된 과제 제출 결과, 프로젝트 산출물, 역량 평가, 수료 여부, 개인별 리포트, 과정별 통계 등은 이번 MVP 범위에는 포함되지 않았습니다. 데이터와 화면이 분리되어 있고 구성원ID를 중심으로 설계되어 있어, 필요할 때 시트와 화면을 추가하는 방식으로 확장할 수 있습니다.
